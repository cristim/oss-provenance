# Native SCANOSS backend contract

The native port follows the official MIT Python implementation pinned at `0c1292bd4d53bc504804411dd42ff1ab0fa7aa76`, with `all_extensions=True`, `bin_file=False`, no snippet stripping, no size truncation, and no HPSM. Attribution and the complete reference source are in `LICENSE-NOTICES/scanoss-winnowing/`.

Fingerprinting retains ASCII letters and digits, lowercases letters, computes CRC32C over 30-byte grams, selects each 64-hash window's minimum, and emits a second CRC32C over its four little-endian bytes when the minimum changes. Line numbers are the current input line at window completion. Only LF advances the line counter. The header includes original-byte MD5 and length; `fh2` follows the reference's opposite-line-ending conversion. These hashes are matching identifiers, not security identities.

`tests/fixtures/scanoss/oracle.json` contains complete WFP outputs produced by the official `scanoss.winnowing.Winnowing` Python class from PyPI `scanoss==1.54.2`. Its installed source was checked byte-for-byte against the pinned GitHub source. Cases cover empty/short inputs, 92/93 normalized-byte boundaries, repeated minima, punctuation/case, Unicode, invalid UTF-8, LF, CRLF, standalone CR, mixed endings, blank lines, and hexadecimal formatting. Python is a development oracle only; normal tests use the recorded outputs and runtime is Rust.

The caller controls network consent before constructing/using `Scanner`. Production endpoints require HTTPS and reject userinfo and fragments. The client rejects redirects, applies a 1..300 second timeout, sends one multipart `file` named `scan.wfp` with `format=plain`, and limits input to 16 MiB, WFP to 64 KiB, and responses to 4 MiB. Limits fail explicitly; fingerprints are never truncated. The wire identity is `source_` plus SHA256 of the caller identity. No local paths or source bytes appear in the multipart body, although fingerprints and byte lengths necessarily disclose information about content.

Every nonempty request requires exactly one response key matching that wire identity and a nonempty array. Only `none`, `file`, and `snippet` kinds are understood. An explicit `none` must stand alone. Missing keys, unexpected keys, duplicate JSON keys or identical matches, invalid known-field types, unknown match kinds, missing ranges, and malformed or out-of-bounds local ranges fail. Numeric ranges must be positive, ordered, and disjoint. Upstream ranges cannot be bounded without retrieving upstream source. Whole-file `all` local ranges become `(1, input line count)`; whole-file upstream `all` is an empty `upstream_ranges`, with the literal preserved in `raw`. Optional absent provenance and license labels remain absent for the evidence layer to resolve. Labels never establish licensing permission.

Empty files do not make a network request. Short, binary/NUL-containing, non-UTF-8, or normalization-empty inputs can still yield whole-file match evidence but return `fingerprintable=false` if no supported text snippet coverage exists. The orchestrator must not treat their negative result as clearance. A negative result for fingerprintable text describes only the service's current database and algorithm, not proof of original authorship.

## Hosted verification

On 2026-09-30, the official public MIT `winnowing.py` fixture above was fingerprinted by the Python reference and POSTed to `https://api.osskb.org/scan/direct`. The response recognized an exact file match at `https://github.com/scanoss/scanoss.py`, `src/scanoss/winnowing.py`, version `v1.49.0`, with `matched=100%`, MD5 `d58d9e6aad6a8574050df90430ed8ffc`, server `5.4.25`, and KB `26.09` / `26.09.29`. The response is retained in `tests/fixtures/scanoss/hosted-public-response.json`; it contains public metadata only. The `pending` field is an upstream component status, not a local policy decision.

The Rust client independently reproduced the exact match on the same date. A second Rust request appended two LF bytes to that public reference, invalidating its whole-file hash. The service returned `id=snippet`, local/upstream lines `26-647`, `matched=95%`, 310 hits, upstream version `v1.25.0`, and file hash `ab0c57d346481ef4c666474f3ef3d745`. Its public response fields are in `tests/fixtures/scanoss/hosted-public-snippet-response.json`; the opaque wire key is replaced by the descriptive fixture ID. Both live Rust tests passed.

Run `cargo test --test scanner live_public_upstream -- --ignored --nocapture` for explicit live Rust-client verification of both paths. These ignored tests upload only fingerprints of the bundled public reference and its two-newline variant, never project source. Ordinary test runs are offline. Hosted availability, response schemas, database versions, and match results can change; a failed live verification is an explicit external-service gap.
