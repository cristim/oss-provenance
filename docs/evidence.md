# Evidence collection

`evidence::collect` downloads public GitHub evidence for a scanner candidate. It requires a repository URL, upstream path, version or commit, and upstream file MD5. It resolves the version through GitHub, pins a full commit and tree, rejects truncated trees, and verifies downloaded source against the scanner's MD5. SHA-256 binds retained artifacts for subsequent review. MD5 verifies the scanner's historical identity; it is not treated as a cryptographic trust anchor.

The collector retains the complete source, including its headers, root and ancestor LICENSE/LICENCE/COPYING/NOTICE/COPYRIGHT/AUTHORS files, source `.license` sidecars, and root `LICENSES/` files. These are review candidates: their location does not establish applicability. Nested exceptions and project use context still need review. A file's explicit SPDX identifier can populate a proposal, but cannot approve it. Scanner license labels are never used as permission.

Every proposal remains pending. Review the full grant text, copyright notices, exceptions and obligations, choose a concrete branch for alternative licensing, and admit the decision separately into trusted policy. The collector neither stages files nor changes policy. When no supported source license declaration exists, artifacts and issues are still returned, with no evidence decision.

Evidence must explicitly declare supported obligations: `artifact_only`, or `source_prefix` with the exact required leading `text` for every file using that source. Source prefixes can contain copyright headers and modification notices. They are checked on all active recorded uses, including deletion-only changes. Collected evidence starts with `unsupported` and a pending-review reason; it cannot clear a match. The reviewer must determine that the configured checks cover the applicable obligations. More complex obligations cannot be silently represented as folder attribution alone.

`evidence::verify_source` re-downloads an admitted source at its full GitHub commit and checks both its MD5 and SHA-256 against trusted evidence. It returns the verified source bytes for local/upstream range comparison. Scanner-provided identity labels alone cannot establish that a local match belongs to this source.

Downloads use only `api.github.com` and `raw.githubusercontent.com`, HTTPS, no redirects, a total deadline of 1 to 300 seconds, 8 MiB per response, 32 MiB total, and at most 64 upstream files. Missing or unsupported candidate metadata and source-hash mismatches produce unresolved issues. Network, HTTP, malformed API responses, incomplete trees and resource-limit failures return operational errors. Private repository credentials are not supported.

`collect_with_scancode_report` optionally accepts a ScanCode JSON report and an explicitly pinned expected version. Run the separately installed scanner with `--license --info --strip-root` over the exact collected upstream tree. The parser requires every collected file once, matching paths and MD5 values, no per-file scan errors, and the pinned tool name/version. It consumes the documented `detected_license_expression_spdx` field, rejects custom LicenseRef expressions, retains the original report, and keeps the resulting proposal pending. The library does not install or execute ScanCode. Its presence and version must be managed by the caller. See the [official ScanCode output contract](https://scancode-toolkit.readthedocs.io/en/stable/reference/scancode-cli/cli-output-format-options.html).

Run the public-reference download test explicitly with `cargo test --test evidence live_public_reference_collects_actual_grant_bytes -- --ignored`. Ordinary tests do not use the network.
